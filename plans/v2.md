# Studybuddy v2 — Plan

## What v2 adds

Three-tab bottom navigation expanding the app beyond flashcards:

1. **Flash cards** — existing screens, plus a progress bar during sessions and a richer completion screen (per-card miss list + "Retry missed only").
2. **Todo** — weekly assignment list with High/Med/Low priority pills and an optional due date (calendar picker). Persisted across sessions.
3. **Notes** — multiple named notes, plain-text, tap-to-edit. Persisted across sessions.

All three tabs are local-only. No backend.

## Design decisions (confirmed with user)

- Priority: **High / Med / Low pills** (red / neutral / muted).
- "For the week" is **soft** — no auto-archive. Completed todos drop to a "Done" section below open ones; user can uncheck to restore or clear.
- Due date: **optional**, backed by a real date picker (native `<input type="date">`).
- Notes: **multiple named notes**, list → tap-to-edit, plain text.
- Session progress bar counts **unique cards done**, not queue length.
- Completion screen: **missed-cards list + "Retry missed only"** button that starts a fresh session over just those cards.
- Bottom nav is **hidden during an active session** (focus mode); visible everywhere else.
- Persistence: **localStorage**, versioned keys (`todos:v1`, `notes:v1`). Durable on home-screen-installed PWAs.

## Data model additions

[src/types.ts](src/types.ts):

```ts
export type Priority = 'high' | 'med' | 'low';

export type Todo = {
  id: string;            // crypto.randomUUID() at create time
  text: string;
  priority: Priority;
  dueDate?: string;      // YYYY-MM-DD, optional
  done: boolean;
  createdAt: string;     // ISO timestamp, for stable sort within priority tier
};

export type Note = {
  id: string;
  title: string;
  body: string;
  updatedAt: string;     // ISO timestamp, list sorts newest-first
};
```

## Storage layer

[src/storage.ts](src/storage.ts) — thin typed wrappers. Keys are versioned so we can migrate later without corrupting existing data.

```ts
const KEYS = { todos: 'todos:v1', notes: 'notes:v1' } as const;

export function loadTodos(): Todo[] { /* JSON.parse with try/catch → [] on corruption */ }
export function saveTodos(t: Todo[]): void { /* JSON.stringify */ }
export function loadNotes(): Note[] { /* ... */ }
export function saveNotes(n: Note[]): void { /* ... */ }
```

Components call `load*` once on mount (via `useState` initializer) and `save*` in a `useEffect` dependent on the state. No external state library needed at this size.

## App.tsx — new top-level shape

```ts
type Tab = 'cards' | 'todo' | 'notes';

// Flash cards tab still owns its own sub-view state machine,
// but lifted into FlashCardsTab.tsx (moved out of App).
export default function App() {
  const [tab, setTab] = useState<Tab>('cards');
  const [sessionActive, setSessionActive] = useState(false);  // hides nav

  return (
    <div className="flex h-full flex-col">
      <main className="min-h-0 flex-1 overflow-y-auto">
        {tab === 'cards' && <FlashCardsTab onSessionActiveChange={setSessionActive} />}
        {tab === 'todo' && <TodoTab />}
        {tab === 'notes' && <NotesTab />}
      </main>
      {!sessionActive && <BottomNav tab={tab} onChange={setTab} />}
    </div>
  );
}
```

`FlashCardsTab` owns the `list | cover | session | results` state that currently lives in `App.tsx`. It reports `sessionActive` upward whenever the sub-view is `session`, so App can hide the nav.

## Flash cards changes

### Progress bar during a session

[src/components/Session.tsx](src/components/Session.tsx):

Existing `progressDone = total - remaining` **over-counts** retries as progress (queue shrinks as items get repushed at the end). Switch to: `uniqueDone = seenRef.current.size - (current pending retries in queue)`. Simpler equivalent — track a `passedRef: Set<number>` of cards that have been marked "Got it" at least once (a retry is considered "unique-done" only on eventual success). Denominator = `deck.cards.length`.

Render at the top, replacing the current plain `"{progressDone} / {total}"` label:

```tsx
<div className="mb-4 flex items-center gap-3">
  <div className="h-2 flex-1 overflow-hidden rounded-full bg-neutral-200">
    <div className="h-full bg-neutral-900 transition-[width]" style={{ width: `${pct}%` }} />
  </div>
  <span className="text-sm tabular-nums text-neutral-500">{passed} / {total}</span>
  <button aria-label="Exit session" onClick={onExit}>✕</button>
</div>
```

### Completion screen

[src/components/Results.tsx](src/components/Results.tsx):

- Keep existing time / first-try / retry stat tiles.
- Replace "Needed retries" list with a richer missed-cards list: show **front and back** of each missed card (user requested full review, not just prompts). Each item is an expandable row — tap to reveal the back (default collapsed to keep the list scannable).
- Add a new primary button: **"Retry missed"** (disabled if `retriedCards.length === 0`), which calls a new `onRetryMissed(cards: Card[])` prop. Below it, existing "Study again" (full deck) and "Back to decks" buttons.

`FlashCardsTab` handles `onRetryMissed` by building an ad-hoc `Deck` (same id, cards = missed subset) and transitioning to `{ kind: 'session', ... }`. Alternatively pass the subset through the view state directly:

```ts
| { kind: 'session'; deckId: string; nonce: number; cardSubset?: Card[] }
```

Session uses `cardSubset ?? deck.cards` as its pool. Cleaner than synthesizing fake decks.

## Todo tab

[src/tabs/TodoTab.tsx](src/tabs/TodoTab.tsx):

UI sections, top to bottom:
1. **Add-row**: text input + priority dropdown (defaults to Med) + optional date picker + "Add" button. Enter key submits.
2. **Open todos**: sorted by priority (High → Med → Low), then by `dueDate` asc (undated last), then by `createdAt`.
3. **Done** collapsible section: same row style but greyed with strikethrough text. Uncheck to restore.

Each [TodoItem.tsx](src/components/TodoItem.tsx) row:
- Round checkbox on left (tap toggles `done`)
- Text (editable on tap — inline rename)
- Priority pill: `bg-red-600 text-white` / `bg-neutral-200 text-neutral-800` / `bg-neutral-100 text-neutral-500` for H / M / L. Tap cycles through priorities.
- Due date: small grey `"Thu 5/8"` if set; tap opens native date input. Long-press or a small ✕ to clear.
- Delete: swipe-left or a trailing `⋯` menu. Default: small trash icon that appears in edit mode (keep v2 simple — just a trash icon visible on all rows, right-aligned, neutral-300).

State: single `Todo[]` in tab. `useEffect(() => saveTodos(todos), [todos])` persists.

## Notes tab

[src/tabs/NotesTab.tsx](src/tabs/NotesTab.tsx):

Two sub-views inside the tab:

1. **List view** (default): `+` button top-right creates a new note (title `"Untitled"`, empty body, opens editor). Each row shows title, 1-line body preview, relative timestamp. Tap row → editor. Long-press or trailing trash icon → delete.

2. **Editor view**: title input on top, large `<textarea>` below filling remaining height. Back arrow returns to list. Autosave: `useEffect` with 300ms debounce writes through to storage on any change. `updatedAt` stamped on every save.

Plain text only — preserve line breaks via `whitespace-pre-wrap` on the list preview. No markdown rendering, no link auto-linking (v3 if needed).

Sub-view state is local to `NotesTab`; doesn't need to leak to `App`.

## Bottom nav

[src/components/BottomNav.tsx](src/components/BottomNav.tsx):

Fixed-height bar (~56px) at the bottom with three equal-width buttons. Safe-area inset padding for iPhone home indicator: `pb-[env(safe-area-inset-bottom)]`.

Each button: icon on top, label below. Active tab = `text-neutral-900`, inactive = `text-neutral-400`. No background fills; a thin `border-t border-neutral-200` above the bar.

Icons: inline SVGs (no icon library). Suggestions:
- Cards: rectangle stack
- Todo: checklist
- Notes: pencil-on-paper

## Styling conventions (carry over from v1)

- Light mode, neutral palette, red/green accents only for destructive/affirmative actions.
- Generous tap targets (min 44×44). Rounded-xl for buttons, rounded-lg for list rows.
- Tailwind utilities; no custom CSS beyond what exists.

## PWA / offline

No config changes. localStorage is available offline; new screens are pure React and ship in the app bundle, so they work identically offline.

## Build order

1. `storage.ts` + types — foundation.
2. `BottomNav` + tab shell in `App.tsx` with stub `TodoTab` / `NotesTab` returning placeholder text, and `FlashCardsTab` hosting the existing flow unchanged. Verify nothing broke; verify tab switching works.
3. Session progress bar + Results missed-cards list + retry-missed flow.
4. Todo tab end-to-end, verify localStorage round-trips after a reload.
5. Notes tab end-to-end, verify autosave + round-trip.
6. Polish pass: safe-area insets, disabled states, empty states ("No todos yet. Add one above." / "No notes yet. Tap + to create one.").

## Verification

1. `npm run dev` — tap each bottom nav icon, confirm the correct tab renders and the active icon highlights.
2. Start a session — bottom nav disappears. Exit — it returns.
3. Session progress bar reaches 100% exactly when Results screen appears. Retry a card twice; confirm the bar only advances on eventual success.
4. On Results, tap "Retry missed" → new session starts containing only the missed subset; Results from *that* session lists only those cards' outcomes.
5. Add 3 todos (one of each priority), check one, set a due date on another, reload the page → all state intact, sort order stable.
6. Create 2 notes, edit one, reload → titles/bodies intact, most-recently-edited appears first.
7. Build + deploy. On installed iPhone PWA, add todos/notes, force-quit the app, reopen → data persists.
